## 2. Exact Optimizations Performed

1. **Backend Database Waterfall Removal**:
   - Converted sequential repository calls in `DashboardService` and `ReportsService` to concurrent `Promise.all` executions.
   - Combined single-table aggregations (`SUM(grand_total)` and `COUNT(*)`) into single SQL SELECT statements.
2. **Database Indexing**:
   - Added 4 composite indexes for store-isolated date range, status, and join queries.
3. **Duplicate Network Request Elimination**:
   - Resolved dual `GET /customers` API fetches on opening `/customers` route.
4. **Route Code-Splitting**:
   - Converted heavy routes to TanStack Router `.lazy.tsx` architecture, reducing initial bundle size.

## 4. Queries Intentionally Kept Sequential and Why

- **Invoice Creation & Inventory Movements (`SalesService.create`)**:
  - Inserting `sales` header record MUST complete before inserting `sale_items` rows because `sale_items` requires the foreign key `sale_id` generated by `sales.id`.
  - Updating stock counts via `inventory_movements` MUST execute sequentially within the transaction (`tx`) after `sale_items` insertion to preserve strict transactional consistency and prevent stock overselling race conditions.

## 5. SQL / Index Migrations Added

Created migration file `backend/src/db/migrations/0021_performance_composite_indexes.sql`:
```sql
CREATE INDEX IF NOT EXISTS "idx_products_store_active" ON "products" ("store_id", "is_active");
CREATE INDEX IF NOT EXISTS "idx_sales_store_created" ON "sales" ("store_id", "created_at");
CREATE INDEX IF NOT EXISTS "idx_sales_store_status_created" ON "sales" ("store_id", "status", "created_at");
CREATE INDEX IF NOT EXISTS "idx_sale_items_sale_product" ON "sale_items" ("sale_id", "product_id");
```

## 6. Duplicate API Requests Removed

- **`/customers` Initial Load**:
  - **Before**: `useQuery({ queryKey: ["customers-all"] })` and `useQuery({ queryKey: ["customers", ""] })` both called `getCustomers()` on mount, sending 2 duplicate `GET /customers` network requests simultaneously.
  - **After**: Single canonical `useQuery({ queryKey: ["customers"] })` loads the initial customer list. `searchResults` query (`queryKey: ["customers-search"]`) is enabled only when a search term is actively entered.
